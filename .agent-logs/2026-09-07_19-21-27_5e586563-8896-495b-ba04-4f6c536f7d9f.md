## 1. My understanding of the product

A chat app that turns *a sentence about a product* into *a short vertical UGC-style ad*, without generating a single frame with AI.

The interesting constraint is that **AI is the editor, not the camera**. The model's job is comprehension and casting: read the site, work out what the thing is and who it's for, then pick a background clip, a GIF, a track, and write the on-screen copy. Everything visible in the output is a pre-existing asset composited by ffmpeg. That's also the honest framing for the walkthrough — "no AI-generated pixels" is a feature, and the demo should say why (rights, speed, cost, the fact that it looks like real UGC rather than uncanny slop).

## 3. Recommended architecture

Single Next.js app. One process, no queue, no database, no worker split.

```
Browser (chat page)
   │  POST /api/chat        → { intent, reply | jobId }
   │  GET  /api/generate    → SSE: brief → assets → render → { videoUrl }
   ▼
Next.js route handlers (Node runtime)
   ├─ lib/intent.ts    Claude → route + chat reply         (1 call)
   ├─ lib/scrape.ts    fetch + cheerio → page text
   ├─ lib/brief.ts     Claude → structured brief           (1 call)
   ├─ lib/assets.ts    Pexels + Giphy + local audio pick
   ├─ lib/text.ts      SVG → sharp → transparent PNG
   └─ lib/render.ts    spawn ffmpeg, one filter_complex
                              ▼
                       /public/out/<id>.mp4  (served directly)
```

**Two AI calls total**, both structured. No agent loop, no chaining, no framework. Progress goes over **SSE** because a 20-second silent spinner reads as broken, and a live "found the product → picked a clip → rendering" trail is the single cheapest thing that makes the demo look finished.

Jobs live in an in-memory `Map`. Single container, one user, sub-30-second lifetime — a database here would be pure ceremony.

**Deploy: Render (or Railway) as a Docker web service, not Vercel.** This is the one architectural call I'd push back on if you disagree, so here's the reasoning: the render step needs a real ffmpeg binary, a writable directory that persists for the length of the demo, and ~20s of uninterrupted execution. On Vercel that means bundling `ffmpeg-static` (~78MB into a 250MB limit), swapping `public/out` for Vercel Blob, and betting on the Hobby duration cap. A `node:20-slim` image with `apt-get install ffmpeg` gives all three for free and matches the local environment exactly, so what I test is what ships. Render's free tier cold-starts slowly — we warm it before recording the walkthrough.

## 4. Next.js approach

Next 16 App Router, TypeScript, **Node runtime pinned** on both routes (`export const runtime = "nodejs"`) — Edge can't spawn a process.

- `app/page.tsx` — client component, the whole chat. No state library; `useState` + a `useRef` for the EventSource.
- `app/api/chat/route.ts` — intent + chat replies.
